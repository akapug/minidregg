# No codec pins

Ember's ruling: “I don't want to pin anything. The code just is and does what it is.”

## Survey

`PersistedCodecTagCensus` walks the Host replay closure, fingerprints definition
bodies, and compares `PersistedCodecShapes.pins`. `PersistedCodecTags` contains
both receiving frames and unrelated hash-domain/schema labels. Its generated
manifest and the shape pins enter `DurableCheckpointCodec.persistedCodecCorpus`.
The census is imported by `Compiler` and `ConsentAnchor`; its self-test is in
`CensusChecks`. The merge gate runs the regeneration script's self/twin checks.
Two planted-census scripts and the modularizer's non-module exceptions also
exist solely for that machinery. The native builder has general companion
artifact checks, not a codec-specific companion stage on this branch.

The encoders are arbitrary functions: `StreamCodec` contains encode/decode and
proofs, not a format description. There are about 100 direct stream definitions
plus compositions, dependent codecs and raw byte encoders. `xmap` can reorder
same-width fields without changing the underlying wire grammar. Consequently
neither a grammar-only hash nor hashing a finite golden corpus establishes the
requested identity. Hashing Lean expressions again would retain the old bug.

## Plan (before implementation)

1. Introduce executable wire-format descriptions at the codec construction
   boundary. Derive encoding, decoding and the tag together. Preserve ordered
   field identity, widths, literal tags and nested formats; normalize harmless
   grouping. Arbitrary handwritten functions cannot acquire a purported exact
   format identity merely by supplying an unchecked descriptor.
2. Move receiving frames onto that boundary and carry the derived identities
   into Store layout descriptors and StoreEpoch. Keep domain separation distinct
   from wire versions. Readers check the derived frame before interpreting bytes.
3. Delete the structural census, shape pins, regeneration script, planted tests,
   imports and gate hooks, with no replacement manifest or version-bump step.
4. Run golden round trips (including suffix consumption and mismatched-frame
   refusal) over the executable formats in a small Lean check without importing
   the Host. Integrate it into the existing build/check entry point.
5. Check changed files and direct importers in the leased dregg-ref tree as
   `lanes`, using bare `lane-check`. Run only relevant Rust checks on the Mac.
   Review named-file diffs and leave the requested commit/push script in target.

A necessary scope constraint: exact extensional equality of arbitrary Lean
encoding functions is not computable. The guarantee must come from the format
language and its interpreter, not from sampling or a more elaborate census.
The existing handwritten/dependent codecs require migration before that
claim can apply to all persisted data; deleting their guard first would leave
silent compatibility holes.

## Working state

The deletion patch is implemented, uncommitted, on `lane/no-pins` at
`70fa7306c`. It removes the census, pins, regeneration and planted tests,
imports, gate hook and structural-fingerprint contribution to StoreEpoch.
Receiving-frame checks remain. **This is not the completed replacement:** the
existing versioned identities still exist, and format derivation and the golden
runner are not implemented. Do not describe this patch as satisfying those two
requirements. The pending design question asks whether the executable-format
contract above is the intended interpretation of exact byte-change identity.

Mac checks: `git diff --check`, shell syntax, Python AST parse, and a source
search finding no remaining references to the deleted machinery in Compiler,
Kernel, scripts, the umbrellas or lakefile. No Rust code changed.
