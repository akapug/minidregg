## Exact representation and ownership

Introduce Theory/ComputedEffect with an ordered Effect value vocabulary: scalar target coordinate/field/value; content target coordinate/canonical ContentResource command; append target coordinate/StreamCell.Append; messageIntent target coordinate/immutable Intent. Content types currently live in Kernel, so move the shared command syntax/codec downward into Theory/Compiler first, or place the concrete sum in Compiler/ComputedEffect rather than manufacture parallel types. Preserve one list order and effect index. An intent has notification versus invocation kind, destination domain/object, immutable descriptor/method identity, payload bytes or exact custody reference, dependencies and authority ceiling as retained actual capability preimage. It contains no signature, authority snapshot, proposed post, current law verdict, ciphertext or release-specific key epoch. Those belong to their respective admission records. Do not serialize the whole later Fn release template as the semantic intent.

Use an evaluator-independent canonical effect codec. A registered typed evaluator's `effectsOf : TypedAbi → Output → Option (List Effect)` owns conversion from its product. Nock's noun product carries versioned tagged typed values, decoded against a new typed output-slot ABI with bounded payload lengths and named target slots. Refuse unsupported/malformed effect kinds. A future typed door should use the same ordered list and record next state as an explicit scalar effect; that extension is not implemented in the selected gate-only API. No externally supplied decoder/callback enters `checkClaim`.

`Run.checkRun` retains exact kernel sample, loaded immutable program/libraries, registered enabled evaluator, signed fuel, exact oracle steps and exact output bytes. Replace BOTH membership tests with ordered list equality. Current `writes.all (· ∈ decoded)` and its converse prove only set equality: they tolerate reorder and duplicates. That is insufficient for append order and message indexes and even permits ambiguous conflicting scalar output. Canonical ordered equality should be the v2 contract; normalize old field-only products only through a separately specified compatibility path, never silently normalize append/message outputs.

ResourceTransaction `commandEffects` derives the expected ordered effects from signed target payloads. Scalar create/write syntax is normalized to field effects only after existing own-object check; ordinary move still has no supported computed lowering. Content/append reuse the existing command syntax. Message intent becomes a dedicated durable intent target payload (or an append to a designated intent stream whose role can only be produced by this controller); it must not be an ordinary mutable field claiming a checked flag. Full byte equality between decoded effects and commandEffects binds recipient, method, payload, dependencies, ceiling, index and target. Signatures already cover canonical Command including its RunClaim and all target payloads through commandBytes/argsDigest/effectsDigest and per-target admission requests. No signed whole-authority root is introduced.

Reuse prepareTarget's current authority/policy/observation checks and checked candidate tuple; include origin intent in the same DataIntent and nullifier transaction. Current law/audience/freeze/device dependencies are receiver-resolved read guards through commit. Scalar/content/append permission checks stay mandatory even when computation succeeds. The typed message clause constrains originating authority ceiling; adapter/transport power never supplies missing semantic authority.

Derive immutable origin after admission from domain, semantics, exact origin transaction digest and effect index. Avoid self-reference: transaction bytes must not contain their own transaction digest. Release admission binds that origin, exact immutable intent, exact ciphertext, destination, current audience/key/device epoch and current release law. Existing Fn only accepts publicPeerable content custody and is not automatically this private protocol. Receiver effect admission consumes original origin identity plus exact intent bytes atomically with application effects/result; different releases and migrations retain this consumption key. Descriptor/incarnation placement is metadata, not a new dedup key. Compaction retains authenticated tombstones or an enforced retirement floor.

## Same-scenario byte and admission accounting

Scenario: one business scalar write plus one N-byte canonical intent; same eventual content custody, current release, receiver effect and receipt. To isolate representation, let object id=1, first intent field=1, N=100, 100 intent bytes each in [1,127], and create the lane initially. Existing StreamCodec naturals use base-255 digits then 255; digestStream is ALSO that natural codec, not fixed 32 bytes. Positive 1..254 numbers take 2 bytes, zero takes 1; zigzag values 1..127 take 2 bytes. Each scalar CREATE byte action is: outer create tag 1 + objectField tag 1 + object id 2 + field digest 2 + int value 2 = 8 bytes. Length field 100 likewise costs 8. List count 101 costs 2: intent lane alone costs exactly 810 bytes in action-list encoding. Rewriting existing slots with expected none uses two write tags plus option tag, adding 2 per action: 1012 bytes. Target metadata, signature, run output jam, full intent codec and business action are excluded equally; this is exact ACTION payload comparison, not invented end-to-end wire cost.

Authored nested-sum message effect encoding has three discriminant bytes, target coordinate zero (one byte), and the canonical messageStream bytes. For a 100-byte messageStream intent it costs 3+1+100 = 104 bytes. This compares the same semantic intent placed into a scalar byte lane; the older Fn-release-template prototype has a different semantic schema and cannot supply its N automatically. Effect list count for business+message adds 2 bytes, as does scalar list counting. At N=100 it replaces 101 semantic field actions with 1 semantic message effect and saves 706 bytes relative to create representation (908 versus rewrite). The typed payload is source-derived arithmetic from effectStream, not measured end-to-end wire savings; Nock output jam size and the root's typed transaction target encoding must be measured from the actual typed program before quoting complete wire savings. For larger IDs/digests use `L(n)=digits255(n)+1`: scalar byte CREATE cost is `2+L(object)+L(field)+L(2*byte)`; length field substitutes `L(2*N)`. This prevents assuming 32-byte digests cost 32 encoded bytes.

Origin-side durable admissions: scalar route 1 business+lane transaction, then at least 1 separate content custody materialization, then 1 release authorization = at least 3. Typed route 1 business+durable-intent transaction, then 1 release authorization = 2 IF origin custody retains the exact release-selectable payload; otherwise it still needs content custody and gains no admission reduction. Both routes then need receiver effect+dedup and receipt recovery. A typed effect that merely stores a ciphertext reference without durable ciphertext availability does not earn the reduced count. Crypto/KEM/signature/fanout costs are equal for equal confidentiality contract and are excluded here.

## General theorem targets and falsifiers

1. Registered-evaluator checked acceptance implies exact ordered effect equality to the kernel's unique derivation, exact signed sample/output and bounded charged steps. Any differing effect list (including reorder/duplicate) cannot be accepted.
2. Atomic prepared transaction theorem connects that equality to the ACTUAL DataIntent target posts and immutable intent custody, with existing current law/capability guards. No extra payload/effect survives lowering; no output effect is omitted.
3. An ordinary-write admission cannot select as a checked intent origin; accepted origin selection implies exact historical signed checked program/effect index and canonical intent, independent of current mutable fields.
4. Fresh release after revoke/freeze refuses; an exact prior committed release can complete without manufacturing a new disclosure. Intent ceiling bounds every release.
5. Original/migrated/rereleased copies share consumption identity and cannot produce two receiver effects; receipt recovery returns original result without rerun. Retired histories never classify previously consumed input as fresh.
6. Semantic migration simulates old method meaning and maintains authority ceiling plus current authorization; field-number equality is insufficient.

Required executable traces: lost origin reply; ordinary field forgery; altered recipient/content/ceiling; reordered and duplicate output effects; content and append coupled to scalar business state; revoke before/after release; stale device generation; crash at custody/release/effect; simultaneous old and migrated requests; restart after compaction. Named general results and receiving-path traces are separate obligations.
