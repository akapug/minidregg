# Consent storage and enrollment review

The consent process runs as the trusted provisioning operator. The source helper uses a SQLite transaction and an atomically replaced head anchor beside the Store directory, so its fixed systemd service needs write access to the Store directory's parent. That access covers every operator-writable entry under that parent; it is not a read-only Store sandbox. The controller account must remain unable to read or write that private directory or its verification credentials.

An independent disposable-file test, `python3 scripts/test-oracle-enrollment-adversary.py`, exercised the bridge lane's actual `consent_storage` function: 6 tests passed. Two additional cases exercise exact-prefix archive recovery, idempotent publication and refusal without overwrite of conflicting partial bytes. Replacing the database or lock changes its retained inode pin; replacing a private, well-formed head anchor may preserve the pin; symlinks, invalid modes, malformed anchor data, duplicate settings keys and noncanonical paths are refused. Platform-specific temporary ancestry and, on macOS, the unavailable `os.listxattr` were mocked. This is not a root installer, deployed systemd, live Store or Mini admission test.

The enrollment transition enforces boundaries including exact old and new configuration, current source authority, a stopped/locked controller, no unresolved work, preserving the existing query and all journal history, and an explicit crash-safe retry that cannot complete a different transition or silently resend an uncertain request.

A separate actual hbox systemd probe used a new private copy of the R2 Store with the qualified mini and Lean consent binary. Under `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes`, `NoNewPrivileges=yes` and only the consent-anchor directory writable, the source SQLite helper returned `Read-only file system (os error 30)` and the client received no successful consent. Adding the copied Store's private parent to `ReadWritePaths` allowed the retained valid 220 request, refused a malformed intent, and repeated both after a service restart using the retained frontier. This exercised real socket activation using the existing unprivileged `nobody` account as the test peer; it did not exercise the dedicated controller namespace, sign, submit, or mutate R3. The unique test units were stopped and removed. Original R2 database and head-anchor hashes remained unchanged.
