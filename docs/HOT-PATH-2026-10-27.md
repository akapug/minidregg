## 2. The design, item by item (what it touches · invariant and its theorem · cost after · size · must not change)

**(a) One resident process per Store, codec in-process. No codec-Host spawn — BUILT (lane/hot-path), re-applied on `mini_sdk::consent`/`local` at lane/hot-path-codec after L2 moved the client's local processes there; `native/resource-client/tests/codec_resident.rs` shows two `mini` processes sharing one child).** The client's pure codec
frames (7–11, `Host.Main.pureCodec`) are already answered by the resident serving Host on the same
socket (`serveFrame` → `pureCodec`); `mini` spawns a *second* 159 MB Lean image per process only
because `local_frame` (`client_consent.rs:1003`) always starts `HOST codec`. Change: `local_frame`
sends 7–11 to the resident Store socket when this binding has one (`exchange_unix`), and a Store-less
client (`--remote`) keeps ONE resident codec Host per `pure_host` binding exactly like the resident
consent provider (`connect_resident`, idle 600 s) instead of one per process. Built here: the
resident is generalised over a kind (`ResidentKind::{Consent, Codec}`: socket `r-`/`c-<binding>` in
the owner-private anchor directory, flock, PID file, peer-uid check, idle exit); `mini codec-resident
--host IMAGE --settings S` holds ONE `HOST S codec` child; `local_frame` connects to it (starting it
when none listens) unless `MINI_CODEC_RESIDENT=0`. The semantic authority stays the client's own
selected image (`MINI_LOCAL_HOST`), never the serving Host. Routing codec frames to the serving
Store socket was rejected: that Host is operator-selected. Invariant: the reply
bytes are the same function of the frame (the codec is pure, `pureCodec` has no state; stated by
`serveCodec`'s doc, no new theorem). Cost after: −2 spawns per write (−0.15…0.4 s). Size M (Rust only).
Must not change: wire bytes, which Host answers which op, the independence of the semantic Host
selection (`MINI_LOCAL_HOST`) from the remote operator.

**(b) `ByteArray` end to end on the serve path.** `serveSession` does `payload.toList` and every
dispatch arm decodes `List UInt8` (W7: 360 instr/B against 8). The codec already has a cursor on
`ByteArray` (`StreamCodec.decodeBytes`, `decodeBytes_eq : decodeBytes c b = decode c b.toList`, 58b3ae50).
Change: `serveFrame` takes `ByteArray`; each arm's first decode uses `decodeBytes`; the lemma that
makes it a representation change is already stated. Cost after: a few KB per op → ~0.3 ms per write.
Honest: a memory/bulk lever (W7's 100 MB for 69 turns), not a latency lever today. Size L (9 K-line
dispatch), S per arm. Deferred behind (f), (a), (d). Must not change: decode results (the lemma).

**(c) Memoised current image per height.** DONE at main for the Host: `Loaded` holds
`engine : DurableEngine.Engine` (CellTable), `roots : RootCache` with `rootsExact`, `ids/txs/spentAt/writesAt`
indices, each with its `Exact` theorem; `resume_eq_resumeFast` is the `@[csimp]` making `resume` run it.
The remaining O(history) walkers (`Image.currentBytes = accepted.reverse.findSome?`, `Image.cellIds`
`eraseDups`) are the *specification* the theorems are about and are no longer on the served path (op 2
flat). Nothing to build; the client-side twin of this item is (f).

**(d) Hashing as `@[extern]` Rust kernels (the Everest pattern) — BEGUN on this branch.**
`cshake256Bytes` and `kmac256Bytes` are the only hash primitives on the path (cell roots, leaf/node/
chain digests, checkpoint and log MACs all go through them). New `native/mini-kernels` (workspace
member; `sha3` crate, already in Cargo.lock): `mini_kernels_cshake256_32`, `mini_kernels_kmac256_32`;
a 40-line C shim does the ByteArray marshalling against the toolchain's `lean.h` (the channel-lib
convention); Lean: `Theory/Sp800185Cshake256Native.lean` `@[extern "mini_cshake256_32"] cshake256Kernel`
whose BODY is the proved fast path, `cshake256Native_eq` (seam body = spec, a theorem), and the
`@[csimp]` moved from `cshake256Bytes_eq_fast` to `cshake256Bytes_eq_native`; the same for KMAC in
`Compiler/Sp800185Kmac256.lean`. Equality of the Rust to the Lean body is NOT a theorem: it is pinned by
(1) `native/mini-kernels/tests/conformance.rs` over Lean-authored vectors (`testdata/lean-vectors.json`,
regenerated by `scripts/kernel-vectors.lean` from the fast path: NIST sample 3, SHAKE256(""), the two
pycryptodome KMAC rows, seeded rows at the rate boundaries) and (2) the tree's own `native_decide`
conformance theorems, which after the csimp evaluate the kernel at every build (the KMAC ones moved to
`Compiler/Sp800185Kmac256Conformance.lean`, see below). The kernel decides nothing. Cost after: Keccak
×14 (WASTE-MODEL W14: 17.4 k → ~1.2 k instructions per permutation), i.e. 170 MB/s → GB/s on every
hash; on today's write shapes the hashing share is small (≤ ~30 ms per write from W K/H prices), so
this is the bulk-cell, cold-open (85 MB state: 0.5 s → 35 ms) and checkpoint lever, not the p50
lever. Size M. Must not change: any digest (the vectors are the proof), domains, framing.
Build consequence (decided, loud): the interpreter resolves an extern by its module's compiled
wrapper, so `#eval`/`native_decide` of anything that hashes needs the seam modules' objects loaded:
`scripts/build-mini-kernels.sh` builds `.lake/native/{libmini_kernels.a, mini_kernels_lean.o}` (link
inputs of every Lean executable: lakefile `moreLinkArgs`, build-native-host.sh, channel-lib) and
`libmini_kernels_lean.so` (shim + kernels + Spec/Fast/Native/Core/Kmac256 objects; lakefile
`moreLeanArgs --load-dynlib`). Run it before `lake build`. Landing this rebuilds the whole tree once
per box (Core's olean and every lean's arguments change).

**(e) Custody as ONE append record per phase.** L2 on `lane/custody` (phase record authoritative;
the per-field `.bin/.json` files become caches repaired from the record by the shared readers). Not
this lane's. Cost after: 55 fsyncs → ~6 per write (−0.27 s SSD, −1 s HDD, the whole HDD tail).

**(f) Consent as an incremental checkpoint — BUILT on this branch (elaborates green against the warm Mac build).** `refresh` is already incremental
(`extendFrom` reads only height+1.., `Basis.extendAppended` admits only the suffix). The O(history)
term is frame 233, `ConsentAnchor.recheckStore`: `transport.read 1 true` + `chainPrefixesStored` over
every record, once per client connection, twice per write. Change: `recheckHeld` reads the entry AT
the provider's height and compares its tag bytes with `Loaded.headTag` (the exact tag whose MAC the
provider verified when it admitted that height). Theorems: `checkHeld_ok` (accepted ⇒ head ≥ height ∧
the tag is the held one), teeth (`checkHeld_refuses_rollback`, `_refuses_other_tag`), satisfiable,
and `trailer_eq_carried` (equal tag bytes carry equal chain/root/frontier/index root). What moves:
eager detection of a self-INconsistent rewrite (old tag left over rewritten records) becomes lazy, at
the verified read that would touch it; a re-tagged rewrite is refused up to a KMAC collision; a
rollback exactly. The exact-prefix guarantee never rested on 233: the signer's state is
`Anchored`/`Verified`, folded from the records it admitted and never re-read. Cost after: consent
flat ≈ 0.2 s at any height (−1 s at 615 records, −16 s at 10k). Size S. Must not change: what the
signer checks (220/221/222), no caching of authorization decisions. **Ruling (ember, 2026-10-27):
ACCEPTED** — detection of a self-inconsistent prefix rewrite moves to the verified read that touches
it; rollback and re-tagged rewrites stay refused; the exact-prefix guarantee (`headTag` equality at
the provider's height + exact prefix) is unchanged.

**(g) SPK STOP hashes the image once per candidate.** The candidate's `SHA256SUMS` pins the image;
STOP compares the pinned digest and re-hashes only when the inode/size changed since the pin (five
re-hashes of 159 MB → one, or zero). Size S, Rust (spk-host), after (a).

**(h) Open = restore the newest checkpoint, fast-forward the suffix; genesis replay = `store audit` — RULED PRIMARY
(ember 2026-10-27: "we should avoid doing actual replays very often; we should keep snapshots and fast-forward them
most often"). STATEMENTS DRAFTED below for the statements auditor; not elaborated, not built.**

Measured cause (dregg-build, 6236826f Host, 483-record Store, ptrace sampler): one full open 160–175 s, 99% in the
genesis World fold (`trackOf` → `foldRecords`); the closure chains of `DFinsupp.update` made it quadratic (fixed as an
in-suffix guard by the compaction, a20dad89 + 6eb74814); what remains is per-turn whole-cell work (Mac, after
compaction: 110 records, fold 8.1 s of a 9.5 s open), still O(history) on every open. The fix is to not replay.

Shape (the HP-DESIGN §1.4 step-1 shape, "the checkpoint is the World"): the checkpoint body (frame v3 → v4, one epoch
bump, riding L1's one re-genesis) carries, beside today's `height, chain, frontier, indexRoot, state`:
`system` (the World's system store, `WorldSystemCodec.systemStream`; the World's cells are `state.cells` decoded) and the
six indexes (`presence, links, ids, txs, spentAt, writesAt`, each in its serialised form). The open reads only the
checkpoint and the entries after it (`readFromCheckpoint`), MAC-checks the checkpoint, verifies the suffix tags from
`body.chain`, and builds `Loaded` as base + suffix (`extend` over the suffix: the per-append path that exists). It reads,
decodes, hashes and MAC-checks no entry below the checkpoint. `trackOf`, the genesis chain and the genesis index rebuild
move to `store audit` (operator, nightly). Every sealer must hold the World: today the LIGHT session seals with no World
(`Compiler/DurableServed.lean:1059`), and `checkpointDifferential` (`DurableReceiverCore.lean:2080`) and the audit
(`DurableStoreAudit.lean:213`) recompute checkpoint bytes; those three move with the body.

Restated open invariants (to be elaborated as `Prop`s in a statements module, e.g. `Compiler/DurableFastForwardSpec.lean`,
names below are the tree's; `ff` = the fast-forward open, `B` = the decoded v4 body, `S` = the suffix records, `T` their
stored tags):

1. **MAC gate (unchanged theorem, restated over v4).** `openSealed key rootBytes bytes = .ok B →
   ∃ sealed, checkpointFrame.decode bytes = some sealed ∧ sealed.body = B ∧ sealed.root = worldRoot rootBytes B ∧
   sealed.mac = checkpointMac key B sealed.root`. Pole (teeth, a tampered snapshot refused BY NAME):
   `checkpointFrame.decode bytes = some sealed → sealed.body.keyId = key.id → sealed.root = worldRoot rootBytes sealed.body →
   sealed.mac ≠ checkpointMac key sealed.body sealed.root → openSealed key rootBytes bytes = .error .badMac`; likewise
   `.rootMismatch` for a body whose recomputed root differs and `.foreignKey` for another key's id. Since the v4 MAC covers
   `bodyStream.encode B`, a changed `system` or index field is a changed body: refused by the same names.
2. **The suffix extends the snapshot (new).** `ff` accepts `S, T` only if `verifyTags key B.height (chainPrefixes B.chain S) T
   = .ok ()` and `T.length = S.length`. Pole: a suffix whose first entry does not chain from `B.chain` (or any later
   entry from its predecessor), or a missing/extra tag, is refused, by `firstBadTag`'s height:
   `verifyTags key B.height (chainPrefixes B.chain S) T = .error m → ff = .error m'` with `m'` naming the height.
3. **Exact over snapshot + suffix (restated `chainExact`/`indexExact`/...).** For `ff = .ok L`:
   `L.height = B.height + S.length ∧ L.chain = chainAfter B.chain S ∧ L.index = B.presence.extendFrom B.height S ∧
   L.links = B.links.extendFrom B.height S ∧ … (ids, txs, spentAt, writesAt likewise) ∧ L.track` is `WorldTrack.advance*`
   of `⟨decodeCells B.state, systemStream.decode B.system⟩` over `S`, decided by `representsCheck` (as today; no
   statement about `track` moves).
4. **What the trust rests on: every checkpoint this Host seals is the replay's value at its height (new, the keystone).**
   For `L` from either open, `storeCheckpoint transport rootBytes L indexRoot` seals a body with
   `B.chain = L.chain = chainAfter L.logStart L.image.accepted` (by `L.chainExact`), `B.presence = L.index =
   PresenceIndex.ofRecords L.image.accepted` (by `L.indexExact`), …, `B.system = (L.track.world?).map (·.system)`.
   Corollary (agreement): for a Store every checkpoint of which was sealed by `storeCheckpoint` under `key`, the
   fast-forward open and the genesis replay produce the same `chain`, indexes and World (`chainAfter_append`,
   `extendFrom_exact`/`ofRecords_append`). Satisfiable: any Store this Host wrote. Premise inhabitation: a checkpoint
   exists at every multiple of `checkpointEvery` that was reached (`checkpointDue`). Teeth: 1 and 2.
5. **Audit is the genesis replay (moved, not weakened).** `store audit` refolds from genesis (`trackOf`), recomputes the
   chain and indexes from every entry, and compares each stored checkpoint's v4 body byte for byte
   (`checkpointDifferential` over v4); a mismatch is refused by height. The nightly runs it once.

Must not change: what a write admits, wire bytes of requests and replies, the MAC key's role, the light open's reads.
Changes, said plainly: a cold open trusts the MAC'd checkpoint for the prefix's indexes, chain and World exactly as it
already trusts it for the prefix's state; a forged checkpoint needs the key, which could already forge the state.
Cost after: O(checkpoint + ≤ 64-record suffix) per open, flat in history. Measure before/after on the ~1.7k-record
Store once a candidate carries it. Second item behind it: `TurnOfIntent` diffing only the keys an intent writes
(statement change, separate audit).

## 3. Build facts that bound every Lean change here (Mac, 12 cores, 10-27)
The Host.Main closure is 3,739 jobs, 51 min on the Mac against ~3 h on hbox's HDD; Host.Main itself
37 s, LawSat 18 s, the Fn/Grain/Lifecycle receivers 10–14 s each. Any change to the hash seam
(Core's olean) or to the lakefile's lean arguments rebuilds that whole closure once per box: (d) lands
as one such rebuild, so it rides with the next full integration build, never alone.
