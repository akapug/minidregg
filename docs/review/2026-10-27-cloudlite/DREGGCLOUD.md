# DreggCloud’s “cloud-lite” experiment

Scope: DreggCloud at checked-out HEAD (`e9ff17a`, 2026-07-12), its documentation, and frozen ClusterVision sessions. I did not build or run anything. DreggNet is the sibling investigator’s scope; where sessions distinguish them, I keep that boundary.

## Bottom line

DreggCloud was a **single-operator, self-hosted House**, not a public multi-tenant cloud-lite platform. It had real receipted Worlds/Rooms, bounded agent executions, a prepaid service economy, and an SPK-serving prototype. It did **not** reach arbitrary shells, notebooks, persistent member applications, or tenant subdomains. Its own deployment guide says “not an unattended public multi-tenant service” (`docs/SELF-HOSTING.md:3-6`). The sessions show this was deliberate sequencing around missing execution, confinement, and restart machinery—not a finished feature later removed.

## What the sessions add

Ember asked whether DreggCloud provided useful agent-platform/Sandstorm self-hosting and called the missing Sandstorm integration “vital” (`claude:b7cdd58a-95d0-4f4e-b623-6629f393f7ec`, prompts **30, 48**; breadstuffs changes authorized at **59**). The diagnosis was three missing pieces: binary execution, serving, and restart-safe authority/capacity. W4 built **serving only**, explicitly leaving execution and jailing elsewhere (`claude:agent-ae84249ac21402703`, prompt **0**). It hit an upstream dirty-tree compile break before verifying against a scratch copy; no later DreggCloud commit closed execution.

An earlier session judged it useful for guided demos/local operators, not untrusted public users (`codex:019f4caa-5fb2-7bc0-8a61-80410a25ebac`, prompt **0**, swarm approved **27**). The Fable session characterized DreggNet as the composted market/hosting prototype and DreggCloud as the surviving custody-shaped House.

## What could come HERE, ranked by stranger value per day

1. **A member-published website: ship Hugo as an SPK.** Mini’s selection review already names Hugo as “markdown in, a whole site out” (`docs/review/2026-10-27-spk-selection/SELECTION.md:175-177`). Use the existing grain `/var/www` and `<grain>-www.demo.dregg.online`; wildcard DNS/TLS, anonymous GET/HEAD, path confinement, and origin separation are already built and box-tested (`deploy/market/INSTALL.md:191-229`). **No new effect.** Risk: low; qualify lifecycle plus one beneath-HTML markdown write and published fetch.
2. **A live notebook: qualify the existing IPython Notebook SPK.** It is concretely in Mini’s index review: `rprqf3`, Jupyter 4.2.2, Jupyter REST, 178 MB, “heavy but agent-gold” (`SELECTION.md:95`); already second-wave (`:180-181`). Smallest honest path: one grain lifecycle row, one REST-driven code execution, one saved `.ipynb`, no network. **No new kernel effect.** Risks: 2016 software, arbitrary-code CPU/memory use, and image size; keep it unopened until sandbox resource ceilings and a restart row pass.
3. **Member-hosted APIs: demonstrate one small REST SPK, not a new hosting control plane.** FileDrop or ExpenseOwl is a smaller qualification candidate than a custom service framework (`SELECTION.md:85,110`). Existing private grain origins and app grants supply the tenancy boundary. Risk: low/medium; this mostly proves the current app story rather than adding a thesis moment.
4. **A two-resident workroom: compose existing Hermes residents.** Give investigator/reviewer separate narrow grants and one bounded purse; use existing admitted `mini_say`/document tools. No DreggCloud runtime or new effect is needed. Risk: prompt-injection and accelerated spend; per-role grants and visible refusals are essential. Lower priority because the tour already demonstrates an agent under law.
5. **Do not add an OS shell, tenant secrets service, friendly subdomains, or a second billing stack for this demo.** A shell belongs inside a qualified SPK if ever offered; Mini’s shell should remain the structured verb interface. Existing grain origins already supply safer micro-domains, existing purses supply visible metering, and DreggCloud has no tenant-secrets design worth porting.
