# SPK freshness: featured applications

**Status: in progress, 2026-10-29.** Every featured application leaves this lane either
(a) as our own signed package built from an identified current upstream and qualified through
install, start, a beneath-HTML operation and read-back, or (b) removed from `FEATURED` with the
reason recorded here. Re-signing an old blob, changing only its label, or treating the Sandstorm
store's `createdAt` as a build timestamp does not qualify.

## Reading the evidence

- **Store date** below is the app index's `createdAt`, not a package build date. The old index
  does not provide a trustworthy build timestamp. Our replacement catalogue entries will carry
  an explicit UTC `packageBuiltAt`, plus `upstreamVersion` and upstream source/release links.
- **Current upstream** comes from the project's release API, official release archive, or pinned
  source commit. A repository push is not called a release. For source-only projects, the exact
  snapshot and its date are shown.
- **Priority** combines agent value and public exposure: P0 is a core scriptable application,
  P1 is valuable but narrower, and P2 is a game, duplicate, or candidate for removal.
- The first four build lanes are Etherpad, EtherCalc, HedgeDoc and Datasette. Build state changes
  to **PACKAGED** only after `spk verify --details`; it changes to **QUALIFIED** only after Mini's
  real lifecycle and app-specific read-back pass.

## Build, key and qualification contract

The light build host is `dregg-forge`, under `/var/lib/spk-fresh/apps/<app>`. The SPK tool comes
from the Sandstorm 308 bundle at `/var/lib/spk-fresh/tools/spk`; the bundle's SHA-256 is
`f1317754765b11f260a757724b28e92d5318d8b277f970c99662c01bd9291879`, and its signature verified
against Sandstorm release-key fingerprint `160D2D577518B58D94C9800B63F227499DA8CCBD`.
No package build runs on the demo host or in its containers.

Each application has its own keyring, exported to `/Users/ember/.dregg-secrets/spk-keys/<app>.keyring`
with mode 0600. New application IDs replace the old Sandstorm IDs in `FEATURED`; the old IDs remain
in this ledger only as historical package references. Reproducibility recipes live under
`apps/packages/<app>/`; private keys and built SPKs do not enter the repository.

Qualification uses `scripts/spk-platform/featured-qualify.sh` and the app-owned write recipe, with
the local pinned package as input. A lifecycle-only pass is not enough. Datasette's read-only HTTP
surface remains an explicit recorded read; every other web app needs its declared write and exact
read-back, or an updated declaration reflecting the current upstream API. Any hbox world-up holds
`flock -o /tank/lanes/world-up.lock` only around world-up, and every world is torn down.
