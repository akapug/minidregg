# Realtime, task and file interfaces: receiving findings

Lane `cx-app-realtime`, 2026-10-28. Declarations remain prototypes until both
native receiving-path and real agent rows pass against a human's same grain.
Fixture tests and extracted source are separate evidence from those rows.

## Existing live failures

Wekan package `2a2c05041cb4285da884d114e4820298` registers a pending
`loginWithSandstorm(token)` for exactly 10,000 ms. The matching HTTP POST
`/.sandstorm-login` takes identity from the bridge's Sandstorm headers and resolves
that pending call. Its catch returns only `Sandstorm login failed`; it intentionally
hides the exception. Four HTTP500 responses alone cannot distinguish a missed
registration/deadline from account creation failure. The harness now records method
send time, each POST duration/status, and a final DDP error code without tokens,
member identities or error bodies. No app mutation is retried.

The first run's op26 unexpected 66-byte reply and op82 enrollment failure cannot
be decoded from `live-evidence.tar.gz`: its 42 files omit both offending binary
frames and the detailed receiving stderr. The successful later serial lifecycle
rows are counterexamples to a reproducible package-install defect, not a diagnosis
of the first failures. Future refusals must preserve the exact framed bytes before
teardown. The original world was already removed when this lane started.

## FileDrop 1.0.6

[Source](https://github.com/zombiezen/filedrop/blob/16b413cd24f23b29ccf7c4ef38a117962cfd31f4/filedrop.go)
exposes GET `/file/` as `{entries:[{name}]}`, PUT `/file/{name}` returning 201 or
204, and exact GET downloads. Names are flat; the declaration refuses subpaths.
Listing is unpaginated and bounded to 1000 returned entries/1 MiB. PUT replaces
an existing filename and offers no package-side ETag precondition. A fresh-grain
scenario checks empty listing, NUL/0xff upload, exact download and listed name.
The fixture is an independent receiver, not a live package result.

## OrgTodo 0.1.7

Package SHA256 `727e6323ee98810826f91b15530e74f46f03c7c24c1269e5ed670411e65b6113`
was downloaded and decoded under a 768 MiB bound (302,067,176 decoded bytes).
The package-ID prefix matches; this extraction does not independently verify the
signature. The installed receiving boundary must still establish signed intake.
Selected actual packaged members were inspected:

| member under `/opt/app/` | SHA256 |
|---|---|
| `build/app.js` | `1b5769be74333d45b18feb97e830030e1967f8fc1474d2a82afdf9d39e5b4491` |
| `build/handlers.js` | `3a9e4ce5465723a5de46fc2fb8ea491f6d980868eaf51c33d438b7421ec9f203` |
| `build/db/Db.js` | `c4627a68397b9f11fdccb3b1db2948e0ebee1415202004518582f1720ebd0656` |

GET `/tasks?resolution=full` returns an `entries` object keyed by task identity.
POST `/tasks/:id?oldhash=...` parses JSON text regardless of Content-Type and
upserts `{id,hash,fulltext}`. An existing identical content hash is a successful
no-op; otherwise a nonempty mismatched old hash returns 409 with current data.
Missing identities are inserted. The declaration requires a previous hash and
derives the new SHA256 from UTF-8 text; it does not expose arbitrary hash input.
This is task-level optimistic concurrency, not a transaction across tasks.
[Upstream handler](https://github.com/fixermark/orgtodo/blob/b904d2ade56b2f89d960c49c97b4bf2b023a54b5/src/handlers.ts)
and database code agree with the inspected packaged receiving path.

## Protocol work still needed

[YATA tag 0.1.2](https://github.com/zenhack/yata/blob/ec525b294d425675c8bcea67928d98533b4253ae/main.go)
has GET `/` for HTML and POST forms for task creation/deletion/completion. Its
`/version/{version}` endpoint is a change notifier, not a semantic read API.
A typed integration needs a repaired package exposing its existing structured
`id/done/descr` data, then a newly signed identity/package and live qualification.
No HTML state scraper has been substituted.

[Prioritize tag 0.5](https://github.com/zenhack/prioritize/blob/9b4929763dab8d74f03df41a9726c0a66df19030/main.go)
has JSON GET `/data`. Header `X-Sandstorm-App-Data-Version: -1` gives an immediate
snapshot; the response's same header identifies its version. POST `/data` requires
that current version (409 on conflict), plus gorilla CSRF cookie and header. The
CSRF token is currently rendered by the root page. A generic bootstrap-token
binding or semantic bootstrap endpoint is needed; state should continue to come
from JSON. Its versioned update code changes in-memory state before writing disk,
so a 500 can follow a visible mutation and must remain uncertain.
